# Security Policy

This policy applies to every repository owned by [@massimoselvi](https://github.com/massimoselvi) that does not have its own `SECURITY.md`.

## Report a vulnerability

Do not open a public issue, pull request, or discussion for a security problem.

1. Open the repository's **Security** tab.
2. Select **Report a vulnerability**. This opens a private security advisory that only you and the maintainer can see.
3. Include the affected repository, version or commit, the impact, and the steps to reproduce.

If the repository does not show **Report a vulnerability**, contact the maintainer privately through the contact options on the [GitHub profile](https://github.com/massimoselvi). Do not include exploit details in the first message. The maintainer will reply with a private channel.

## Supported versions

Only the latest commit on the default branch and the latest published release receive security fixes. Archived repositories receive no fixes.

## What to expect

These are targets for a personal, best-effort project. They are not guarantees.

| Step | Target |
| --- | --- |
| Acknowledge the report | 5 business days |
| Give a first assessment | 10 business days |
| Release a fix for a confirmed high or critical issue | 30 days |

The maintainer works in the Central European time zone. The maintainer will credit you in the advisory unless you ask to stay anonymous.

## Scope

In scope: source code, build and release workflows, and dependencies of a repository owned by @massimoselvi.

Out of scope: forks of third-party projects (report to the upstream project), archived repositories, and findings that need physical access or a compromised maintainer account.
