# Accessibility

This statement applies to every repository owned by [@massimoselvi](https://github.com/massimoselvi) that does not have its own `ACCESSIBILITY.md`.

## Goals

- Web interfaces target [WCAG 2.2](https://www.w3.org/TR/WCAG22/) level AA.
- Command-line tools give readable text output, do not depend on color alone to show meaning, and respect the `NO_COLOR` environment variable where they use color.
- Documentation uses headings in order, descriptive link text, alternative text for images, and text versions of diagrams.

## Known barriers

These repositories are personal projects. Most of them are libraries, examples, or command-line tools, and nobody has audited them for accessibility. Some older example projects can have barriers that are not documented.

A repository-specific `ACCESSIBILITY.md` lists the known barriers of that repository, if any are known.

## Report a barrier

Open an issue with the **Bug report** form. Start the summary with `Accessibility:`, and include:

- The page, screen, command, or document that has the barrier.
- What you tried to do, and what blocked you.
- The assistive technology, browser, and operating system that you use, if you want to share them.

If you cannot use the issue form, contact the maintainer through the contact options on the [GitHub profile](https://github.com/massimoselvi).

## What to expect

Support is best effort. The target is a first response within 5 business days. A barrier that blocks a main task of a project has the same priority as a functional bug.
